# 예비창업자 제출/검증 코파일럿 PRD v0.1
- Owner 팀: Product/Engineering (TBD)
- 최종 업데이트: 2025-12-27

## 1. 개요·목표
- 문제 정의(Pain지표 포함):
  - Q2(제출/통과) 예비창업자는 지원사업/대출/경진대회 등 **압박 이벤트(마감 D-7~D-14)** 상황에서 “무엇을/어떻게 써야 하는지”를 몰라 **초안 작성에 3일 이상**이 소요되고(실패 KPI: `초안 완성 TTV > 72시간`), 양식/용어/재무 항목에서 **누락·오류가 발생**한다(실패 KPI: `필수 항목 누락 ≥ 1건`, `손익/재무 계산 오류 ≥ 1건`).
  - 사용자는 템플릿/복붙/유튜브/교육/고가 컨설팅 등 대안을 탐색하지만, **개별 상황 적용**이 어렵거나 **비용·리드타임**이 커서 실행이 지연된다(실패 KPI: `마감 D-1 시점 “제출본 미완성”`).
  - 의사결정 단계에서 **품질 불신 + 표절/유사도 + 보안 우려**가 결제/사용 전환을 막는다(실패 KPI: `보안/유사도 우려로 “제출본 다운로드(Export)” 미수행`).
  - 사용 단계에서 “내 맥락과 미묘하게 다른” 결과물로 인해 **수정/편집 난이도**가 높다(실패 KPI: `초안 생성 후 편집/수정에 120분 이상 소요`).
  - 유지 단계에서 Q2는 목적 달성 후 이탈이 자연스럽고, 따라서 제품은 Q2의 단기 성공을 만들면서 **Q2→Q1(검증/실행관리)**로 이어지는 여정을 제공해야 한다.
- 목표(Desired Outcome 수치화):
  - Q2 목표: **1차 제출본을 3시간 내 완성**(기준선 3일 → 목표 3시간)하고, **필수 항목 누락 0건**, **계산 오류 0건**, **반려 0~1회 수준**으로 통과 확률을 개선한다.
  - Q1 목표(전환): 제출 이후 2주 내 **핵심 가설 3개 검증**, **Top3 리스크 완화안 확보**, **투자자/팀 설득 가능한 근거(시장규모·단위경제) 확보**로 “검증/실행관리” 루프를 만든다.
- 성공 지표(북극성/보조 KPI):
  - 북극성 KPI:
    - **제출 가능 초안 완성률(Submit-Ready Draft Rate)**: `초안 생성 후 24시간 내 Export 완료 비율`
      - 기준선: 템플릿/복붙 기반 프로세스에서 **초안 완성에 3일** 소요(간접 기준선: `TTV = 72h`)
      - 목표: `TTV ≤ 3h`를 만족하는 Export 비율 ≥ **60%** (베타 4주)
      - 측정 주기/창구: 주간, 제품 이벤트 로그(`draft_generated`, `export_completed`, `time_to_export_minutes`)
  - 보조 KPI:
    - **Time-to-Value (TTV)**: `첫 생성(draft_generated) → 첫 Export(export_completed)` 소요시간
      - 기준선: 3일(=72h)
      - 목표: p50 ≤ **180분**, p90 ≤ **360분** (베타 4주)
      - 측정 주기/창구: 주간, 이벤트 로그 + 대시보드
    - **양식 적합성(필수 항목 누락 건수)**: `템플릿 필수 항목 검증 실패 건수`
      - 기준선(가정): 대안(템플릿/복붙/수작업) 기준 `누락 ≥ 1건` 발생률 **60%**
        - 확정 계획: 베타 시작 전 **사전 벤치마크(n≥20, 동일 태스크)**로 기준선 재측정 후 업데이트
      - 목표: Export 시점 `누락 0건` 비율 ≥ **90%**
      - 측정 주기/창구: 주간, 서버 검증 로그(`required_field_missing_count`)
    - **재무/손익 계산 오류율**: `재무 섹션 계산 검증 실패 비율`
      - 기준선(가정): 대안(엑셀/수기 계산) 기준 `오류 ≥ 1건` 발생률 **50%**
        - 확정 계획: 베타 시작 전 **사전 벤치마크(n≥20, 동일 태스크)**로 기준선 재측정 후 업데이트
      - 목표: `오류 0건` 비율 ≥ **95%**
      - 측정 주기/창구: 주간, 계산 엔진 검증 로그
    - **1회 통과 근접도(반려 횟수 Proxy)**: `사용자 자기보고 반려 횟수(제출 후)` 또는 `반려 사유 체크리스트 충족률`
      - 기준선(가정): `반려 ≥ 2회` 경험 비율 **40%** (사전 벤치마크/설문으로 확정)
      - 목표: 베타 4주 내 `반려 0~1회` 달성 비율 ≥ **60%**
      - 측정 주기/창구: 월간, 사용자 설문 + 체크리스트 충족률(서버 검증)
    - **Q2→Q1 전환율**: `Export 완료 후 14일 내 “검증 보드(Validation Board) 첫 생성” 비율`
      - 기준선: 0% (기능 미제공 상태)
      - 목표: ≥ **15%**
      - 측정 주기/창구: 격주, 이벤트 로그(`validation_board_created`)

## 3. 사용자 스토리와 수용 기준(AC, Acceptance Criteria)
- Story 1 (Q2 / 템플릿 기반 제출본 생성):
  - Story: As a **Q2 예비창업자**, I want **기관/목적에 맞는 템플릿을 선택하고 Q&A로 입력**해서, so that **3시간 내 제출 가능한 초안을 Export**할 수 있다.
  - AC:
    - Given 템플릿(예: 예창패/대출/대회)과 “필수 항목 체크리스트”가 제공될 때, When 사용자가 Q&A를 완료하고 “초안 생성”을 누르면, Then **p95 60초 이내**에 초안이 생성되고 `draft_generated`가 기록된다.
    - Given 사용자가 필수 항목 중 일부를 비워둔 상태일 때, When Export를 시도하면, Then **누락 항목 목록(필드명+가이드)**이 표시되고 Export가 차단되며 `required_field_missing_count ≥ 1`이 기록된다. (실패 케이스 1)
    - Given 사용자가 템플릿을 완료했을 때, When Export하면, Then Export 산출물은 **템플릿 필수 섹션 100% 포함**(누락 0건)해야 하며 `export_completed`가 기록된다.
- Story 2 (Q2 / 재무·손익 자동 생성 및 검증):
  - Story: As a **Q2 예비창업자**, I want **재무/손익을 질문 응답 기반으로 자동 생성**해서, so that **계산 오류 없이 제출 요건을 충족**할 수 있다.
  - AC:
    - Given 사용자가 매출/원가/고정비 등 입력을 제공했을 때, When “재무 생성”을 실행하면, Then 산출된 표의 합계/연산은 **계산 검증을 통과**해야 하고(오류 0건), 실패 시 오류 원인과 수정 가이드를 제공한다.
    - Given 사용자가 숫자 필드에 문자/음수 등 비정상 입력을 했을 때, When 저장/생성을 시도하면, Then **클라이언트/서버 양쪽 검증**으로 거부되며 오류 메시지를 제공한다. (실패 케이스 2)
    - Given 입력이 정상일 때, When 재무 섹션을 Export하면, Then Export 결과는 **재무 섹션 포함 + 주요 지표(매출/비용/손익) 일관성**을 유지해야 한다.
- Story 3 (사용 / 편집기에서 맥락 보정):
  - Story: As a **Q2/Q1 사용자**, I want **생성된 문서를 쉽게 수정/편집**해서, so that **내 상황에 맞는 논리 일관성 있는 제출본**을 만들 수 있다.
  - AC:
    - Given 초안이 생성되어 있을 때, When 사용자가 섹션을 클릭하면, Then **2초 이내**에 편집 가능한 형태로 로드된다(p95).
    - Given 사용자가 문장을 수정했을 때, When “논리 점검(Consistency Check)”을 실행하면, Then 최소 **3개 타입의 체크(누락/모순/용어정합)** 결과를 제공하고 수정 제안을 함께 보여준다.
    - Given 사용자가 변경사항을 저장하면, When 버전이 생성되면, Then **직전 10개 버전**까지 되돌리기가 가능하다.
- Story 4 (의사결정 / 보안·신뢰 패키지):
  - Story: As a **보안·표절이 걱정되는 사용자**, I want **데이터 저장/삭제 옵션과 로그를 명확히 확인**해서, so that **안심하고 입력/생성/다운로드**할 수 있다.
  - AC:
    - Given 사용자가 “저장하지 않음(세션 종료 시 삭제)” 모드를 선택했을 때, When 세션을 종료하면, Then **24시간 이내** 서버 저장 데이터가 삭제되고 삭제 로그가 남는다.
    - Given 사용자가 “내 데이터 학습 미사용” 정책을 확인할 때, When 정책 페이지를 열면, Then **수집 항목/보존 기간/삭제 방법**이 명확히 표시된다.
    - Given 사용자가 Export를 수행할 때, When Export가 완료되면, Then Export 산출물에는 **생성 시각/템플릿/버전** 메타데이터가 포함된다(추적 가능성).
- Story 5 (Q2→Q1 전환 / 검증 보드 Lite):
  - Story: As a **Q2 사용자**, I want **제출 이후 다음 행동(검증/실행관리)**을 안내받아서, so that **2주 내 가설 3개를 검증**할 수 있다.
  - AC:
    - Given Export가 완료되었을 때, When “다음 단계로 전환”을 누르면, Then **기본 가설 카드 3개 템플릿**이 생성된다(고객/시장/가격).
    - Given 사용자가 가설에 근거(링크/메모)를 추가했을 때, When “검증 상태 업데이트”를 하면, Then 상태는 **Backlog/In Test/Validated/Invalidated** 중 하나로 저장된다.
    - Given 14일이 경과했을 때, When 사용자가 미검증 가설이 남아 있으면, Then **주간 리마인드(인앱)**가 표시된다.

## 4. 기능 요구사항(Functional)
- MSCW 우선순위와 근거(대안 대비 가치)
  - Must (MVP):
    - **제출/통과 템플릿 + 필수 항목 체크**: 대안(템플릿/복붙) 대비 “누락 방지”를 제품이 책임짐.
    - **Q&A 입력 기반 재무/손익 자동 생성 + 계산 검증**: “재무 공포” 제거, 오류 0건 목표를 시스템적으로 보장.
    - **초안 자동완성 + 즉시 데모/샘플 출력**: 탐색/의사결정 단계에서 전환을 올리는 핵심.
    - **편집기(Editor) + 버전 관리(최근 10개)**: “내 맥락과 다름” 문제를 해결하지 못하면 사용 단계에서 이탈.
    - **보안/신뢰 패키지(정책/저장·삭제 옵션/감사 로그)**: 의사결정 병목(보안/표절/유사도)을 해소.
    - **Export(다운로드/내보내기)**: Q2의 목적 달성(제출본 확보)의 완료 조건.
  - Should:
    - **Q2→Q1 전환 플로우(실행 로드맵/주간 체크)**: Q2의 자연 이탈을 “검증/실행”으로 연결.
    - **논리 점검(Consistency Check) 리포트**: 품질 불신 완화(모순/누락/용어정합).
  - Could (1스프린트 내 구현 가능 후보):
    - **기관별 템플릿 “추가 요청” 폼 + 내부 운영자 큐**: 템플릿 확장 속도를 높이는 운영 기능(개발 1스프린트).
    - **내보내기 포맷 옵션(기본: PDF, 추가: DOCX)**: Export 편의성 증대.
  - Won’t (v0.1 범위 제외):
    - **B2B/B2G 파트너용 관리자(기관 템플릿 관리 포털)**: Phase 2로 이관.
    - **전면 자동 시장/경쟁 데이터 수집 크롤링**: 법/정책/품질 리스크가 커서 v0.1 제외.
  - 의존성:
    - LLM API(생성/요약/리라이팅) + 비용/레이트리밋 정책
    - 계산/검증 엔진(재무 산식), 템플릿 스키마(필수 항목 정의)
    - 로그/대시보드(제품 분석), Export 렌더러(PDF)

## 5. 비기능 요구사항(NFR, Non-Functional Requirement)
- 성능: p95 응답 ≤ ___ ms
  - 초안 생성 요청 API p95 ≤ **60,000ms**, 편집기 로드 p95 ≤ **2,000ms**, 템플릿/체크리스트 조회 p95 ≤ **800ms**
- 신뢰성: 월 가용성 ≥ ___%, 오류율 ≤ ___%
  - 월 가용성 ≥ **99.5%**
  - API 5xx 오류율 ≤ **0.5%**, Export 실패율 ≤ **1.0%**
- 보안/비용: ___
  - 보안:
    - 저장 모드 2종: (a) **세션 종료 시 삭제(최대 24h 내 삭제)**, (b) 기본 저장(보존 **30일**, 사용자 요청 시 즉시 삭제)
    - 접근 통제: 사용자별 프로젝트 접근 제어 + 감사 로그(조회/Export/삭제)
    - 데이터 정책: 사용자 입력/산출물은 **모델 학습에 사용하지 않음**(정책 명문화)
  - 비용:
    - 생성 비용 모니터링(요청당 토큰/원가) + 일일 예산 초과 시 기능 제한(예: 초안 생성 횟수 제한)
- 모니터링 항목: 로그·대시보드·알림 기준
  - 로그/지표:
    - `time_to_export_minutes`, `required_field_missing_count`, `finance_validation_error_count`
    - 초안 생성 p95, Export 실패율, 편집기 로드 p95
  - 알림 기준:
    - 초안 생성 p95 > 90s(15분 지속), Export 실패율 > 2%(30분), 5xx 오류율 > 1%(15분)

## 6. 데이터·인터페이스 개요
- 핵심 엔터티, 주요 필드
  - User: `user_id`, `segment(Q1/Q2)`, `consent_flags`
  - Project: `project_id`, `template_id`, `mode(Q2/Q1)`, `created_at`
  - Template: `template_id`, `name`, `required_fields[]`, `sections[]`
  - Answer: `project_id`, `field_key`, `value`, `validated(bool)`
  - Draft/DocumentVersion: `document_id`, `version`, `content`, `created_at`
  - ExportJob: `export_id`, `format(pdf/docx)`, `status`, `completed_at`
  - AuditLog: `actor_id`, `action`, `resource_id`, `timestamp`
- 외부/내부 API 개요(입출력·제약)
  - `GET /templates` → 템플릿 목록/필수 항목
  - `POST /projects` → 템플릿 선택 후 프로젝트 생성
  - `POST /projects/{id}/generate-draft` → 초안 생성(비동기 가능)
  - `POST /projects/{id}/validate` → 필수 항목/재무 검증
  - `POST /projects/{id}/export` → PDF/DOCX 내보내기
  - `POST /projects/{id}/delete` → 데이터 삭제(정책 준수)

## 7. 범위(In/Out), 리스크·가정·의존성
- In/Out 명시
  - In(v0.1):
    - Q2 템플릿 기반 제출본 생성(사업계획/재무) + 검증 + 편집 + Export
    - 보안/신뢰 패키지(저장/삭제 옵션, 정책, 감사 로그)
    - Q2→Q1 전환 “검증 보드 Lite”(가설 3개 템플릿, 상태관리)
  - Out(v0.1):
    - 기관/은행별 “관리자 포털” 및 템플릿 마켓플레이스
    - 자동 크롤링 기반 시장/경쟁 데이터 수집
- 리스크(최소 3개), 가정·의존성(ADR 링크)
  - 리스크 1: 생성 결과의 **환각/논리 오류**로 품질 불신이 확대될 수 있음
    - 대응: 필수 항목/재무는 **규칙 기반 검증** + “논리 점검 리포트” 제공, 중요 주장에는 근거 링크 유도
    - ADR: `GPT-PRD/adr/ADR-0002-generation-and-validation.md`
  - 리스크 2: **보안/유사도(표절) 우려**로 결제/사용 전환이 막힐 수 있음
    - 대응: 저장/삭제 옵션, 정책 명문화, 감사 로그, Export 메타데이터 제공(추적 가능성)
    - ADR: `GPT-PRD/adr/ADR-0003-data-retention-and-security.md`
  - 리스크 3: Q2의 **자연 이탈(다운로드 후 해지)**로 LTV가 낮을 수 있음
    - 대응: Export 직후 “검증/실행관리(Q1)”로 이어지는 전환 플로우와 가설 보드 제공
    - ADR: `GPT-PRD/adr/ADR-0001-dual-track-q2-q1.md`
  - 가정(검증 계획 포함):
    - 가정 A: Q2는 “3시간 내 제출본” 가치가 있으면 유료 전환한다 → 베타에서 전환율/완성률로 검증
    - 가정 B: 재무 검증을 제공하면 “숫자 공포”가 유의미하게 감소한다 → 설문(만족도) + 오류율로 검증
  - 주요 의존성:
    - LLM 제공자 정책/비용/레이트리밋
    - PDF Export 품질(한글 폰트/표 렌더링), 분석/로그 인프라

## 8. 실험·롤아웃·측정
- 베타 채널, 실험 가설/측정/성공 기준
  - 베타 채널:
    - Q2: 예창패/대출/대회 준비 커뮤니티, 대학 창업동아리
    - Q1: 린스타트업 커뮤니티/AC·VC 네트워크
  - 실험 1 (핵심 가치 검증 / Q2):
    - 가설: “템플릿+체크+재무검증+편집+Export”를 제공하면 사용자의 TTV가 72h→3h로 단축된다.
    - 설계: 베타 사용자 n≥50, 4주 관찰(코호트)
    - 측정: `time_to_export_minutes`, Export 완료율, 누락/오류 0건 비율
    - 성공 기준: p50 TTV ≤ 180분, Submit-Ready Draft Rate ≥ 60%
  - 실험 2 (의사결정 병목 / 보안·신뢰):
    - 가설: “저장/삭제 옵션 + 정책 가시화”는 생성/Export 전환을 개선한다.
    - 설계: A/B(정책 노출 강/약), n≥200 세션
    - 측정: `draft_generated → export_completed` 전환율
    - 성공 기준: 전환율 **+10%p** 이상 개선
  - 실험 3 (Q2→Q1 전환):
    - 가설: Export 직후 “검증 보드 Lite”를 제공하면 14일 내 전환율이 증가한다.
    - 설계: A/B(보드 제공/미제공), n≥100 Export
    - 측정: `validation_board_created` / Export
    - 성공 기준: Q2→Q1 전환율 ≥ 15%
- 경쟁 대안 대비 벤치마크 계획
  - 대안: 템플릿/복붙, 일반 LLM 프롬프트, 수작업(엑셀/PPT)
  - 벤치마크 항목(수치 비교 목표):
    - 속도: 대안 대비 **10배 이상** 빠른 TTV(최소 72h→≤7.2h, 목표 3h)
    - 정확: “필수 항목 누락”과 “재무 오류”를 대안 대비 **80% 이상 감소**, 목표는 Export 시점 0건
  - 측정 도구: 태스크 기반 사용자 테스트 + 서버 검증 로그 + 설문(신뢰/안심 척도)
