# ADR-0002: 생성(LLM) + 검증(규칙/계산) 결합 아키텍처

- 상태: Accepted
- 날짜: 2025-12-27
- 맥락(Context):
  - Q2 사용자는 “제출 가능한 품질”을 요구하며, 품질 불신이 의사결정 병목이다.
  - 단순 생성만으로는 “필수 항목 누락 0건 / 계산 오류 0건”을 보장하기 어렵다.
- 결정(Decision):
  - 문서 생성은 LLM을 사용하되, 아래는 **결정적으로 규칙 기반 검증**을 적용한다.
    - 필수 항목: 템플릿 스키마(required_fields) 기반 누락 검증
    - 재무: 산식/합계/일관성(예: 매출-비용=손익) 규칙 검증
  - Export는 검증 통과를 필수 조건으로 하고, 실패 시 “수정 가이드”를 제공한다.
  - “논리 점검(Consistency Check)”은 v0.1에서 최소 3개 체크(누락/모순/용어정합)로 제한한다.
- 대안(Alternatives):
  - LLM 단독(검증 없음): 품질/신뢰 리스크가 커서 목표 지표 달성 불가.
  - 규칙 기반만: 맥락/서술 품질이 낮아 사용성 저하.
- 결과(Consequences):
  - 장점: 품질 목표(누락/오류 0)에 시스템적 안전장치 제공, 신뢰 개선.
  - 단점: 템플릿 스키마/검증 규칙 유지보수 비용 증가.
